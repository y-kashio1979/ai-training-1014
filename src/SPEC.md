# シャッフルランチ 仕様書

## 1. 目的・背景

- **利用者**: 社員(想定 〜30人)
- **困りごと**: いつも同じ人とランチに行ってしまう。他の人を誘いたいが、声をかけづらい。
- **成功の状態**: 知り合いが増えている。
  - アプリ内では測らず、アンケートで確認する。

## 2. 画面フロー

参加を申し込む → グループが決まる → お知らせが届く

1. **参加を申し込む**: 利用者が、その週のランチに参加したいときにボタンで申し込む。
2. **グループが決まる**: 締切時刻に、申し込んだ人から自動でグループが作られる。
3. **お知らせが届く**: グループ発表をアプリ画面上で確認する(お店の候補も表示する)。

## 3. 決定済みの仕様

| 項目 | 内容 |
|---|---|
| 開催頻度 | 毎週 |
| サイクル | ランチ当日の朝に締切 → 即グループ発表 → 当日ランチ |
| 時刻 | 締切・ランチ開始の時刻は設定値として変更可能にする |
| 申し込み | 毎週ボタンで申し込む(その週に行ける人だけが参加) |
| グループ人数 | 4人。割り切れない場合は3人グループを混ぜる(例: 10人 = 4+3+3) |
| 組み合わせ | 完全ランダム(過去の同席履歴や部署による制約はなし) |
| お店 | 事前に登録したお店を候補として表示するだけ(割り当てはしない) |
| お知らせ | アプリ画面上の表示のみ |
| 締切後 | 取り消しのみ可。グループは再編成しない |
| 利用者の識別 | 社員名簿から自分の名前を選ぶ(暫定) |

## 4. 未決定事項

- **認証(ログイン)方式**: 後から追加できる設計にする。
- **管理者の操作**: 参加者の確認、グループの手動調整、名簿の管理などが必要かどうかを後で決める。
- **締切・ランチ開始の具体的な時刻**: 設定値として変更可能にする。
- **参加者が極端に少ない場合の扱い**: 3人未満のときにどうするかは未確認。要確認。

## 5. 技術メモ

- 既存の Next.js 16 (App Router) / TypeScript / Tailwind の構成を使う。
- 想定規模が小さいため、データ保存は簡易なもので足りる。具体的な保存先は実装時に決める。
- 締切時刻に自動でグループ分けするため、定期実行の仕組みが必要になる(実装時に検討)。
- 認証を後付けできるよう、利用者の識別を差し替え可能な作りにする。

## 6. 範囲外

- メール・Slack・Teams などへの通知
- 過去の同席履歴や部署によるグループ分けの制御
- お店の自動割り当て
- アプリ内での成功指標(知り合いの増加など)の集計
