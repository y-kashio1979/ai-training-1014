# イシュー作成

`gh` コマンドで GitHub にイシューを作成する。作成前に必ずユーザーの確認をとる。

## 手順

1. **内容を把握する**
   - 引数や会話の内容から、何についてのイシューかを把握する。
   - 「やること」や「終わったといえる条件」を書くための情報が足りなければ、ユーザーに質問する。推測で埋めない。

2. **下書きを作る**
   - タイトル: 内容が一目で分かる短い日本語にする。
   - 本文: 次のテンプレートに従う。

   ```markdown
   ## やること

   - [ ] (実施する作業を具体的に)

   ## 終わったといえる条件

   - [ ] (完了を客観的に判断できる条件)
   ```

   - 「やること」は作業の内容を具体的に書く。
   - 「終わったといえる条件」は、第三者が見て達成したか判断できる書き方にする(例: 「`npm run lint` がエラーなしで通る」)。
   - 言語は日本語。

3. **GitHub に作る前に、内容を見せて確認をとる**
   - タイトルと本文をそのままユーザーに表示する。
   - 「この内容で作成してよいですか?」と尋ね、承認を待つ。承認があるまで `gh issue create` は実行しない。
   - 修正の指示があれば直して、再度見せて確認をとる。

4. **承認されたら作成する**
   - 本文はシェルの引用符の問題を避けるため、スクラッチパッドなどの一時ファイルに書き、`--body-file` で渡す。

   ```bash
   gh issue create --title "タイトル" --body-file <本文ファイルの絶対パス>
   ```

   - ラベルや担当者は、ユーザーが指定したときだけ `--label` / `--assignee` で付ける。

5. **結果を報告する**
   - 作成されたイシューの URL を伝える。
   - 失敗した場合は、エラーの内容をそのまま伝える(`gh auth status` で認証状態を確認してよい)。

## 注意

- 確認なしで作成しない。イシューは外部に公開されるため、承認は毎回とる。
- `.env` などの機密情報や秘密の値を、タイトルや本文に含めない。
